# Справочник по Саудии

Агрегатор объявлений из телеграм-каналов: собирает посты из многих каналов,
разбирает их в карточки и **склеивает повторы**, так что одно объявление
показывается один раз, а не десять. Локации — одна из категорий справочника,
а не отдельный проект.

## Зачем

В каналах одно и то же объявление публикуют заново каждый день, новое тонет
в потоке старого, и найти нужное невозможно. Справочник разворачивает это:
категории вместо ленты, одна карточка на одно объявление, свежесть считается
по последнему появлению.

## Быстрый старт

```bash
uv sync                                        # зависимости
cp .env.example .env                           # вписать ключи
uv run python scripts/import_locations.py      # 204 локации в базу
uv run python -m ksa serve --reload            # http://127.0.0.1:8000
```

Сайт работает уже на этом шаге — на реальных локациях, без Telegram и без
ключа Anthropic. Ключи нужны только для сбора и разбора новых объявлений.

## Как это устроено

```
каналы → raw_message → listing_occurrence → listing → выдача
 сбор      архив          разбор            склейка   ранжирование
```

- **`raw_message`** — архив сырых постов. Пишется один раз и не меняется:
  из него можно пересобрать всё заново, когда меняется логика разбора.
- **`listing_occurrence`** — результат разбора одного поста.
- **`listing`** — каноническая карточка. Много вхождений → одна карточка.

Ежедневный цикл:

```bash
uv run python -m ksa collect     # забрать новое из каналов
uv run python -m ksa parse       # разобрать и склеить дубли
uv run python -m ksa review      # посмотреть спорные склейки
uv run python -m ksa publish     # выпустить в выдачу
uv run python -m ksa stats       # что в базе
```

## Дедупликация — ядро проекта

Ни один признак по отдельности не надёжен: телефон повторяется у агента
с десятком квартир, текст переписывают, фото берут из интернета. Поэтому
считается взвешенная сумма (`src/ksa/dedup/matcher.py`):

| Сигнал | Вес |
|---|---|
| Тот же личный телефон | +0.60 |
| Тот же telegram-контакт | +0.40 |
| То же фото (перцептивный хеш) | +0.40 |
| Текст почти идентичен | +0.50 |
| Совпала цена | +0.15 |
| Цена расходится больше чем на четверть | −0.35 |
| Разное число комнат | −0.20 |
| Контакт общий для всего канала | +0.10 вместо +0.60 |

- **≥ 0.70** — склеиваем автоматически.
- **0.55–0.70** — серая зона: карточка публикуется, но попадает в очередь
  модератора (`ksa review`). Молча склеивать нельзя, молча плодить дубли —
  тоже.
- **Контакт, встретившийся в 15+ постах одного канала**, считается подписью
  канала, а не признаком объявления, и почти не влияет на склейку.

## Ранжирование и деньги

Порядок выдачи: `оплаченный подъём → свежесть → релевантность`.
Монетизация — это таблица `promotion` и одно слагаемое в `ORDER BY`
(`src/ksa/api/main.py`). Больше нигде о ней знать не нужно: включается,
когда справочником начнут пользоваться.

## Разбор моделью

`src/ksa/parse/extract.py` вытаскивает из поста категорию, город, цену,
комнаты и площадь через structured outputs. Контакты моделью **не**
извлекаются — регулярки надёжнее и бесплатны, а на контактах держится
вся склейка.

По умолчанию `claude-opus-5`. Для разбора большого архива дешевле поставить
в `.env` модель попроще (`KSA_PARSE_MODEL=claude-haiku-4-5`) и пускать
через `submit_batch` — Batch API даёт ещё вдвое дешевле.

## Картинки на Cloudflare R2

Фото лежат под префиксом `ksa/` в бакете `tafsir-data` (тот же, что у
tafsir-app — у него уже включён публичный доступ). Путь на R2 совпадает
с полем `listing.photo` в базе, поэтому адрес картинки — это просто
`KSA_MEDIA_BASE_URL + "/" + photo`.

```bash
./upload_r2.sh              # залить новые фото (инкрементально)
./upload_r2.sh --dry-run    # посмотреть, что зальётся
```

Благодаря этому статическая выгрузка весит 316 КБ вместо 11 МБ: сайт
раздаёт только разметку и данные, картинки идут с R2.

Если `KSA_MEDIA_BASE_URL` не задан, всё работает по-старому — фото отдаёт
бэкенд из `data/`, а выгрузка забирает их с собой.

## Публикация на GitHub Pages

```bash
uv run python scripts/export_static.py   # собрать docs/
git add -A && git commit -m "обновил данные" && git push
```

В настройках репозитория: `Settings` → `Pages` → Source **Deploy from
a branch**, ветка **main**, папка **/docs**.

Это снимок, а не живой сайт: GitHub Pages не запускает Python, поэтому
весь справочник лежит в `docs/data/listings.json` и фильтруется в браузере.
Годится, пока карточек тысячи. Когда пойдёт поток объявлений, понадобится
хостинг с бэкендом.

## Структура

```
src/ksa/
  ingest/collect.py    сбор из Telegram (Telethon)
  parse/extract.py     разбор поста в структуру
  dedup/               нормализация, pHash, сравнение, кластеризация
  api/main.py          HTTP-API и раздача сайта
  pipeline.py          связка: разбор → склейка → публикация
web/                   фронтенд без сборки: index.html, styles.css, app.js
docs/                  статическая выгрузка для GitHub Pages (пересобирается)
migrations/001_init.sql  схема
scripts/               импорт локаций, сборка статики
upload_r2.sh           заливка фотографий на Cloudflare R2
data/locations.json    204 локации из первого канала
data/photos/           201 фотография к ним (копия — на R2)
```

## Что стоит знать о данных локаций

- Города определены по адресу и координатам: Медина 96, Мекка 49, Джидда 12,
  Янбу 7, Риджаль-Альма 6, Абха 5, Таиф 5, Эр-Рияд 4, Аль-Ула 3;
  у 17 город не определился.
- Категории проставлены автоматически, часть неточна: 24 места осели
  в «Другое», в «Транспорт» попали и вокзалы, и парковки.
- У части мест в названии стоит арабский адрес из Google Maps вместо
  человеческого имени — это видно в выдаче и требует ручной правки.
- Один пост канала описывает до 11 мест сразу, поэтому ссылка на пост
  не уникальна; записи различаются по `external_id`.

## Хранилище

Сейчас SQLite: на MVP объёмах этого достаточно, а дедуп считается на Python
и от возможностей БД не зависит. Схема (`migrations/001_init.sql`) написана
переносимой на Postgres — переезд понадобится, когда карточек станут сотни
тысяч и понадобится полнотекстовый поиск.

## Правовая сторона

Мы переопубликовываем чужие объявления. Поэтому:

- ссылка на исходный пост хранится и показывается на каждой карточке;
- по запросу автора карточка снимается (`status = 'rejected'`);
- крупные каналы лучше звать в партнёры, а не молча парсить: мы возвращаем
  им трафик, и это же канал роста.
